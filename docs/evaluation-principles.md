# CrucibleX 评测原则

CrucibleX 是独立的算子评测框架。它的目标是让一个算子结论可以被复现：声明算子契约，生成或捕获具有代表性的输入，在已声明的资源环境中执行，以明确的预言机评估行为，并保留其他工程师能够检查或重放的证据。

## 产品边界

ATK 提供领域经验、可用资产和工作流证据，但不是实现蓝图。CrucibleX 可以为仍被用户交换的资产提供可选导入器或报告适配器；这些适配器必须位于核心领域模型之外，且在不改变执行语义的前提下可被移除。

## 核心问题

核心中的每一项功能都必须至少增强下列一个问题：

1. 声明了什么算子行为？
2. 哪个输入空间能够支持或挑战该结论？
3. 哪个资源化环境执行了它？
4. 哪个预言机评估了观察到的行为？
5. 哪些证据使结果可复现、可审计？

只复刻历史实现细节而不能回答上述问题的功能，不属于核心。

## 不可妥协的边界

- 领域契约独立于调度器、设备 SDK、存储引擎和报告格式。
- 在相同 Case 契约、seed 和生成器版本下，输入生成必须确定。
- 调度器负责放置工作和收集结构化结果，不定义测试语义。
- 执行器负责适配算子 API 与运行时，不拥有 run 级比较或报告。
- Driver 负责持久化 artifact、派生比较、汇总与重放材料。
- 只有具备可执行门禁、结果级硬件证据和保留 artifact 时，才能声明硬件能力。
- 插件仅用于生成、执行、比较和设备策略等易变策略。

## 版本化证据契约

`manifest.json` 和每条 `results.jsonl` 记录都携带显式 schema 版本。只要版本 1 保持向后兼容，读取器就接受缺失版本字段的历史记录；未知未来版本必须被拒绝。每次 schema 变更都必须说明迁移策略、更新 fixture，并保留产生结果的 CrucibleX 版本。

CSV、Markdown 和面向 dashboard 的输出都是 JSON 契约的投影，不是规范状态。

## 演进顺序

1. 强化算子、输入、资源、预言机和证据契约。
2. 以 elementwise、broadcast、reduction、多输出和可选参数等代表性算子族验证契约，而不是按历史模块逐项迁移。
3. 扩展代表性算子族与确定性生成。
4. 将 CPU、GPU、NPU 和 ACLNN 结论变为可重复的硬件门禁。
5. 仅为已确认的用户工作流增加导入和导出适配器。
6. 仅在结果契约和 artifact 生命周期稳定后增加运营界面。

## 明确非目标

- 不为 ATK 兼容而重建 Celery、调度器持有的数据库或远程任务服务。
- 不为每一个历史转换步骤创建独立命令。
- 不将可选后端 SDK 变成基础依赖。
- 不将本地 smoke 成功当作硬件能力声明。
